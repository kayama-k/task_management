# Task Board 要求分析書

- 作成日: 2026-08-25
- プロジェクト: task_management / Task Board(トレロ風タスク管理アプリ、架空案件)
- 位置づけ: 本書は [requirements.md](requirements.md)(要件定義書)の前段として、依頼者(=開発者本人)のニーズを整理したものである。

## 1. 背景

依頼者は、仕事・プライベートを問わず今後の予定やタスクを継続的に管理していきたいと考えている。
現状の管理方法を振り返り、何が不足しているかを分析したうえで、開発するアプリの要求として整理する。

## 2. 現状(As-Is)

- 依頼者は現在、カレンダーアプリやメモアプリなど、既存のデジタルツールを組み合わせてスケジュール・タスクを管理している。
- これらのツールは「日付」を軸にした一覧性には優れるが、「そのタスクが今どういう状態か(未着手/進行中/完了)」を軸にした一覧性は備えていない。

## 3. 課題(Pain Points)

| 課題 | 詳細 |
|---|---|
| **進捗状況が一目でわからない**(最重要) | 日付順の一覧が中心で、状態別(未着手/進行中/完了)に俯瞰できない |
| 状態変更の手間 | 状態を変えるたびにメモを書き直す/チェックを付け替える必要がある |
| 継続利用のモチベーション | 見た目が画一的で、使い続けるモチベーションを保ちにくい |
| 日時管理の柔軟性不足 | 日時入力を強制されがちで、未定タスクを気軽に扱えない |

## 4. 要求(依頼者が求めること)

課題を踏まえ、依頼者が求める要求を整理する。対応する要件定義書の項目・優先度もあわせて示す。

| 要求 | 対応する課題 | 対応する要件定義書の項目 | 優先度 |
|---|---|---|---|
| 状態(未着手/進行中/完了)ごとに列分けし、進捗を一目で把握したい | 進捗状況が一目でわからない | 4.1 リスト管理 | 高(最大の課題に直結する中核機能) |
| ドラッグ操作で状態(列)を簡単に移動したい | 状態変更の手間 | 4.4 ドラッグ&ドロップ | 高(進捗把握を実用的に使うために必須) |
| 日時は必要なタスクだけ任意で設定できるようにしたい | 日時管理の柔軟性不足 | 4.3 予定日時(任意設定) | 中(付加価値。上位2つほど致命的ではない) |
| 設定した日時は、期限が近い/過ぎているものを視覚的に示したい | 進捗状況が一目でわからない、日時管理の柔軟性不足 | 4.3 予定日時の色分け表示 | 中(付加価値。上位2つほど致命的ではない) |
| 背景の色・画像をカスタマイズし、使い続けたくなる見た目にしたい | 継続利用のモチベーション | 4.5 背景カスタマイズ | 低(継続利用のための付加価値) |

## 5. 目的(To-Be)

カレンダー・メモアプリでは得られない「状態(進捗)を軸にした一覧性」を、トレロ風のカンバンボードによって実現する。
これにより、依頼者は自分の今後の予定・タスクを、進捗状況ひと目で把握しながら、ストレスなく管理できるようになる。
